# OMX agent framework integrations

Copy-and-run examples that connect [OMX](https://pypi.org/project/omx-hyperliquid/) (`omx-hyperliquid`
0.1.3), a non-custodial Hyperliquid execution engine with a stdio MCP server, to the agent frameworks
developers use most. Every example has a matching `verify/verify_*.py` that starts the OMX server through
the **same connection function**, lists the tools and, where the framework allows it without a model,
calls one read-only tool. The verify scripts never call an LLM, so they run without any API key. By
default the server runs in `--demo` mode (a simulated venue, no key or network), so the first run already
gets real answers.

- OMX is non-custodial: your funds stay in your own Hyperliquid account, and OMX signs only with an API /
  agent wallet that can place and cancel orders but cannot withdraw. It never asks for your main key.
- An agent orders only inside the limits you set: intents above the approval threshold or the daily agent
  budget wait for a human (`omx approvals approve <id>`); an agent can turn the kill switch on but only a
  human can clear it; no MCP tool can change limits, fees or keys.
- The 1 bp (0.01 %) builder fee is charged only after you approve it from your own wallet
  (`omx approve-builder`); `omx init --no-builder` sends no builder code, and you can revoke at any time.
- OMX makes no claim about trading performance. It is not available to persons in the United States,
  Ontario or sanctioned territories (Hyperliquid Terms of Use).

## Layout

```
examples/omx_mcp.py                 how the server is launched (OMX_MCP_COMMAND, OMX_MCP_ARGS), shared by all
examples/openai_agents_agent.py     OpenAI Agents SDK      agents.mcp.MCPServerStdio
examples/langchain_agent.py         LangChain / LangGraph  langchain.mcp.MCPAdapter + create_agent
examples/claude_agent_sdk_agent.py  Claude Agent SDK       ClaudeAgentOptions(mcp_servers=...)
examples/pydantic_ai_agent.py       PydanticAI             pydantic_ai.mcp.MCPToolset + StdioTransport
examples/crewai_agent.py            CrewAI                 crewai_tools.MCPServerAdapter
verify/verify_<framework>.py        the same connection, no LLM
verify_all.py                       runs every verify script, writes out/verify_results.json
requirements/*.txt                  pinned versions used for the results above
```

The files are named `<framework>_agent.py` rather than `<framework>.py` because a script called
`langchain.py` or `crewai.py` would shadow the package it imports.

## Choosing the OMX mode

| `OMX_MCP_ARGS` | What the server does |
|---|---|
| `--demo` (default) | The real OMX engine, policy checks, approval threshold, agent budget and kill switch on a simulated venue inside the server process. No key, account, daemon or network; no real order can be sent; every answer carries `"demo": true`. Prices are a random-walk model, not Hyperliquid data. |
| `--inspect` | No config, daemon or key. Lists the 9 tools; every call returns `NOT_CONFIGURED`. |
| `--config omx.toml` | Real use (start on testnet). Same as `omx-mcp --config omx.toml`: the server holds no key and forwards each call to `omx daemon`. |

To trade: `omx --config omx.toml init --account 0xYOUR_MAIN_ADDRESS --key-path <agent key file>` once,
keep `omx --config omx.toml daemon` running in its own terminal, then set `OMX_MCP_ARGS="--config omx.toml"`.
`OMX_MCP_ARGS` also accepts a JSON list for paths with spaces: `["--config", "C:\\my dir\\omx.toml"]`.
`OMX_MCP_COMMAND` overrides the server executable (default: `omx-hyperliquid` in the same environment,
else on `PATH`).

## Run the verification

Windows (PowerShell); use `bin/` instead of `Scripts\` elsewhere.

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements\main.txt
python -m venv .venv-crewai
.venv-crewai\Scripts\python -m pip install -r requirements\crewai.txt
.venv\Scripts\python verify_all.py --update-readme
```

`verify_all.py` runs CrewAI with `.venv-crewai` (override with `OMX_VERIFY_PYTHON_CREWAI`) and every other
framework with the interpreter that runs it. It points `OMX_MCP_COMMAND` at the `omx-hyperliquid` of that
interpreter, so all five clients start the same OMX server. Why two environments: OMX 0.1.3 requires
`mcp>=2.3`, while CrewAI pins `mcp<2`. MCP stdio talks over a pipe, so a client in one environment and the
server in another work together; nothing is patched.

The Claude Agent SDK check starts the Claude Code runtime bundled with the SDK with `setting_sources=[]`
and a throwaway `CLAUDE_CONFIG_DIR` under `out/claude_cwd`, connects without a prompt and reads
`get_mcp_status()`. The SDK calls MCP tools only inside a model turn, so that row lists tools but makes
no tool call.

## Run an example (needs a model key)

```
.venv\Scripts\python examples\openai_agents_agent.py          # OPENAI_API_KEY
set LANGCHAIN_MODEL=openai:<model> & .venv\Scripts\python examples\langchain_agent.py
.venv\Scripts\python examples\claude_agent_sdk_agent.py       # Anthropic credentials
set PYDANTIC_AI_MODEL=openai:<model> & .venv\Scripts\python examples\pydantic_ai_agent.py
set OMX_MCP_COMMAND=.venv\Scripts\omx-hyperliquid.exe & .venv-crewai\Scripts\python examples\crewai_agent.py
```

Each example asks the agent to read the limits, quote ETH and preview (not submit) a 0.01 ETH buy. In
the default `--demo` mode the answers come from the simulated venue and are marked `"demo": true`; in
`--inspect` mode every tool answers `NOT_CONFIGURED`, which the agent should report.

## Notes on framework APIs (checked 2026-11-05)

- **LangChain**: `langchain-mcp-adapters` is archived; MCP lives in `langchain[mcp]>=1.4` as
  `langchain.mcp.MCPAdapter` (beta, FastMCP-based). `langchain-mcp-adapters` 0.3.2 also pins `mcp<2`.
- **PydanticAI**: `MCPToolset` over a FastMCP transport replaces `MCPServerStdio`.
- **Anthropic Messages API**: its MCP connector needs a server publicly exposed over HTTP; local stdio
  servers cannot be connected directly. For OMX use the Claude Agent SDK (above), or your own MCP client
  with the Anthropic SDK's client-side MCP helpers.
